# 주문 매칭 엔진

아직 명세를 쓰기 전이다. 기본기를 끝낸 뒤 `SPEC.md`와 뼈대 코드를 만든다. 20~30시간 정도 걸릴 것 같다.

거래소의 주문장(order book)을 만든다. 가격이 좋은 주문이 먼저, 가격이 같으면 먼저 들어온 주문이 먼저 체결된다. 신규, 취소, 정정 주문과 지정가, 시장가, IOC, FOK 같은 주문 유형이 담긴 이벤트 로그를 재생해서 체결 내역과 호가 스냅샷을 만든다. 같은 로그를 넣으면 결과도 항상 같아야 한다.

구조는 엔진 하나만 상태를 바꾸게 하고, 앞쪽에서는 코루틴 `Channel`로 주문을 받아 넘기고, 뒤쪽에서는 `SharedFlow`로 시세를 내보내는 형태다. 지연에 민감한 시스템이라 `Price`, `Qty`, `OrderId`를 value class로 만들어 박싱을 없애고, 주문 하나를 처리하는 동안 객체를 하나도 만들지 않는 걸 목표로 한다. 마지막에는 G1과 ZGC에서 p99 지연이 어떻게 다른지 비교하는데, 14장(GC)에서 본 걸 실제 코드에 써 보는 부분이다.

주문 유형별 규칙을 정리한 명세, 이벤트 로그 파서, 시나리오 파일, 지연 측정 도구, 테스트는 뼈대로 준비해 두고, 주문장 자료구조, 매칭 로직, 게이트웨이, 시세 Flow, 할당 줄이기는 직접 구현한다.

검증은 `./check kotlin project matching-engine`으로 한다. 시나리오별 체결 내역을 golden과 비교하고, property 테스트로 "매수 최고가가 매도 최저가보다 높은 채로 남지 않는다", "수량이 사라지거나 늘어나지 않는다" 같은 불변식을 확인한다. 주문당 할당량 테스트도 있다. GC별 지연 분포는 재 보기만 하고 테스트로 검증하지는 않는다.

관련 섹션: 03(sealed, value class), 04(inline), 05(자료구조 선택), 07(거절 사유 모델링), 09(Java에서 쓰는 API), 11~13(Channel, SharedFlow, 가상 시간 테스트), 14(할당량과 GC별 지연)
