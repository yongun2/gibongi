# 02. 값 의미론·포인터·구조체·메서드

> 아직 설계 메모만 있는 섹션이다. 예제와 실습은 이 메모를 바탕으로 만든다.

> 선행 01 · 4h · 관련 변화: `new(expr)`(1.26)

**핵심 질문**

1. Go에서 "대입"은 정확히 무엇을 복사하나? 포인터를 쓰면 무엇이 달라지나?
2. 값 리시버와 포인터 리시버는 기계적으로 무엇이 다르고, 언제 무엇을 쓰나?
3. 임베딩은 왜 상속이 아닌가? Java의 템플릿 메서드 패턴을 그대로 옮기면 무엇이 깨지나?
4. 구조체는 메모리에 어떻게 놓이고, 필드 순서가 왜 크기를 바꾸나?

**README**

- ① 내부 동작
  - **복사 규칙**
    - 대입, 인자 전달, 반환, range 변수는 모두 **값의 비트 복사**다. 구조체는 필드 전부, 배열은 원소 전부가 복사된다.
    - 흔히 "참조 타입"이라 부르는 것들도 실은 작은 값(헤더나 포인터)을 복사하는 것이다. **무엇이 복사되고 무엇이 공유되는지** 표로 정리한다:

      | 타입 | 복사되는 것 | 공유되는 것 | Sizeof (arm64) |
      |---|---|---|---|
      | string | {ptr, len} | 바이트 (불변) | 16 |
      | []T | {ptr, len, cap} | backing array | 24 |
      | map, chan | 포인터 1개 | 런타임 구조 전체 | 8 |
      | func | 포인터 1개 | 클로저 환경 | 8 |
      | interface | {type/itab, data} | data가 가리키는 값 | 16 |
      | [N]T, struct | 전부 | 없음 | 내용 크기 |

      Sizeof 값은 **[로컬]** 확인.
  - **포인터**
    - 포인터 산술은 없다(unsafe 제외). GC가 추적한다.
    - 필드와 원소를 가리키는 내부 포인터(`&s.f`, `&a[i]`)를 허용한다. 이 포인터 하나가 객체 전체를 살려 둔다.
    - 지역 변수의 주소를 반환해도 안전하다. 탈출 분석이 그 변수를 힙으로 옮긴다(`moved to heap: x`). C와 다른 점이다.
    - 생성 방법: `new(T)`, `&T{}`, 1.26부터 `new(expr)` **[RN 1.26, 로컬]**.
  - **메서드**
    - 메서드는 리시버를 첫 인자로 받는 함수다. 메서드 표현식 `T.M(v)`, `(*T).M(p)`로 직접 확인할 수 있다.
    - 값 리시버는 복사본을 받는다.
    - `v.M()`에서 `v`가 주소를 가질 수 있으면 컴파일러가 `(&v).M()`으로 바꿔 준다. 그래서 맵 원소나 함수 반환값에는 포인터 메서드를 호출할 수 없다.
  - **메서드 집합**: `T`는 값 리시버 메서드만, `*T`는 둘 다 가진다. 06장에서 이것이 인터페이스 만족 여부를 결정한다.
  - **임베딩**
    - 임베딩은 필드와 메서드를 승격(promotion)하는 문법일 뿐이다.
    - 승격된 메서드의 리시버는 **여전히 내부 타입**이다. 내부 타입의 메서드가 다른 메서드를 부르면 바깥 타입이 정의한 같은 이름 메서드가 아니라 자기 것을 부른다. 동적 디스패치가 없다.
  - **비교 가능성**: 모든 필드가 comparable이면 `==`가 되고 맵 키로 쓸 수 있다. 슬라이스·맵·함수 필드가 하나라도 있으면 불가다.
  - **레이아웃**
    - 필드는 선언 순서대로 놓이고, 각 필드는 자기 정렬 경계에 맞춰진다. 그 사이에 패딩이 생긴다.
    - 구조체 크기는 최대 정렬의 배수다. `struct{}`는 0바이트다.
    - 객체 헤더가 없다. Java 객체는 12~16바이트 헤더를 가지고, 배열에는 참조만 담는다. Go의 `[]T`는 T를 연속으로 담는다.
- ② 차이
  - Java는 원시 타입을 빼면 전부 힙 객체 + 참조다. Go는 전부 값이고 포인터는 선택이다(Java `record`나 Valhalla value class에 가깝다).
  - 불변 키워드(`final` 필드)가 없다. 값 복사로 방어하거나 비공개 필드 + 메서드로 막는다.
  - 상속, 추상 클래스, `protected`가 없다. 조합 + 인터페이스(06) + 함수 필드로 대신한다.
  - 생성자가 없다. `NewT` 함수, zero value 설계, (필요할 때) 함수형 옵션으로 대신한다.
- ③ 판단 기준
  - **포인터 리시버**를 쓸 때: 상태를 바꾼다, 크다(대략 수십~백 바이트 이상이면 측정), 복사하면 안 되는 필드(`sync.Mutex`)가 있다, 다른 메서드가 이미 포인터 리시버다(일관성).
  - **값 리시버**를 쓸 때: 작고 불변인 값 타입(`time.Time`, 좌표, 범위).
  - 필드 순서 최적화는 대량 배열(페이지 테이블 엔트리 수백만 개)일 때만 의미 있다.
  - **임베딩**은 "is-a"를 표현할 때가 아니라 "내부 타입의 메서드를 그대로 노출하고 싶을 때"만 쓴다. 대부분은 이름 있는 필드가 낫다.
- 함정
  - 값 리시버 메서드에서 상태를 바꾸면 변경이 사라진다.
  - `m[k].count++`는 컴파일 에러다. 읽고, 고치고, 다시 쓰거나 `map[K]*V`를 쓴다.
  - Mutex가 든 구조체를 값으로 넘긴다(13장에서 vet `copylocks`로 확인).
  - 임베딩으로 템플릿 메서드 패턴을 구현하면 오버라이드가 호출되지 않는다.
  - 생성자마다 `return &T{}`를 쓰는 습관이 불필요한 힙 할당을 만든다(11장).
